# Content and Layout Reference

Read this after the initial design pass for every new or revised site. Use the
agent's internal todo or step tool to inspect the page in order and apply the
changes, not merely to record that the reference was read.

## Choose a reading path

Choose one primary reading path based on the content:

- Use an F-shaped path for content-led pages, product explanations, and
  information-heavy surfaces. Establish a strong left-side anchor for the
  primary idea or action, then let related information branch to the right.
- Use a Z-shaped path for short landing pages when the story naturally moves
  from introduction to supporting proof and then to a clear action.

F and Z describe how attention should move, not a requirement to draw a
literal letter. Keep the chosen path consistent across sections. Do not make
the user relocate the main idea by alternating the dominant content from left
to right. A page that repeatedly reverses its focal side is a zig-zag, not a
clear reading path.

## Give content a reason to exist

Before finalizing the page:

1. State the page's purpose and primary action in one sentence.
2. Identify the main anchor and the next useful piece of information.
3. Give every section one unique job and one primary message.
4. Remove claims, labels, metadata, statistics, CTAs, and sections that repeat
   another part of the page or do not help the user's decision.
5. Prefer the fewest sections needed to complete the narrative.
6. Put secondary detail behind progressive disclosure when it does not belong
   in the main path.

Do not invent filler to make a page feel complete. Do not turn every idea into
a feature card, tab group, accordion, metric band, or numbered section.

## Use grids only when they help

Use a multi-column grid when items are genuinely comparable, equally important,
concise, and easier to scan together. The number of items does not determine
the number of columns.

Prefer one featured item, a vertical list, an anchored detail relationship, or
progressive disclosure when one idea is primary or the items have different
importance. Do not use a four-column band as a default treatment for four
pieces of content.

## Keep hierarchy visible

Use one dominant heading for each section. Descriptions, helper text, metadata,
and actions support that heading; they must be subordinate through scale,
weight, spacing, placement, and contrast. Do not style supporting copy as a
second heading or place it at the same visual level.

Do not add decorative numbers to headings, labels, sections, cards, or
metadata. Numbers are permitted when they genuinely number an ordered list or
are essential product data. Do not use `/` in rendered user-facing copy,
headings, labels, navigation, metadata, or decorative notation.

Avoid decorative preheadings and editorial index labels. If a short label is
necessary, it must provide useful context and remain subordinate to the main
heading.

## Render and prune

Inspect the actual rendered page at wide and narrow sizes. Ask:

- Can the page be scanned in a sensible order without reading every word?
- Is the primary anchor obvious immediately?
- Do supporting elements branch from it rather than compete with it?
- Can any section or content block be removed without weakening the message?
- Are there repeated structures that make the page feel dense or mechanical?

If the page is long, dense, label-heavy, or difficult to scan, remove or
restructure content before adding more visual treatment.
