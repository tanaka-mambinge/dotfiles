# Full-Direction Variation Workflow

Read this reference whenever the user requests options, variants, alternate
directions, or multiple versions of a UI.

## Non-negotiable variation rule

Build each direction from an independent structural brief. Do not duplicate
the first direction and reskin it. Do not copy its page skeleton, hero
composition, section rhythm, navigation pattern, dominant asset treatment,
typography system, component structure, or interaction recipe and then make
cosmetic changes.

Use the agent's internal todo or step tool to create a separate checklist for
each direction. Do not create a tracking document in the project. Do this
planning before implementing any direction, and do not mark a direction ready
until its checklist and the final comparison are complete.

## Shared foundation

Keep the underlying user goal, primary task, required content, and core
functionality stable unless the user asks for behavioral alternatives. The
design directions may differ radically while still solving the same problem.

Every direction must independently use a clear F-shaped or Z-shaped reading
path when appropriate. It must not introduce decorative numbering,
slash-separated notation, filler sections, confused hierarchy, or unjustified
four-column groups.

## Build distinct directions

Give each direction a clear thesis: describe the experience it is trying to
create and the organizing idea that makes its choices coherent.

Before building, define independently for every direction:

- design thesis and page architecture;
- hero composition and content placement;
- navigation and primary-action strategy;
- content relationships, hierarchy, and copy approach;
- type pairing, scale, and text composition;
- spacing, density, components, and control relationships;
- surfaces, depth, imagery role, and visual treatment;
- interaction states, motion character, and transition behavior;
- responsive behavior and the intended reading order.

These are design decisions, not labels to fill in after copying an existing
page. If two briefs already share the same structure, rewrite one before
implementation.

A complete variation changes the whole visual and interaction language across
multiple dimensions:

- composition and layout structure;
- information hierarchy and content relationships;
- wording, copy tone, and content emphasis;
- typography and type scale;
- spacing and density;
- component shapes and control relationships;
- surfaces, depth, borders, and visual treatment;
- interaction states, motion character, and transition behavior.

No two directions should use the same combination of page architecture, hero
composition, dominant asset treatment, shape language, surface or material
language, typography system, button/control language, and motion language.
This applies even when the copy and required content are shared.

Do not call a direction complete when it only changes colors, corner geometry,
shadows, one font, minor spacing, or isolated decoration. If the same layout,
copy structure, component relationships, and interaction model could be reused
unchanged, the options are cosmetic rather than genuinely different.

Do not reuse the same dominant asset in the same role across directions. If the
available asset pool is limited, change its role, crop, scale, composition,
masking, or surrounding layout so it is not the same visual anchor in every
direction.

Do not let every direction fall back to squared cards, identical button
treatments, flat surfaces, or the same hover response. Rounded, organic,
tactile, translucent, soft-depth, layered, editorial, diagrammatic,
high-contrast, playful, and other treatments are possible sources of
inspiration, but choose them from the product context rather than presenting
them as a fixed menu or asking the user to select from a catalogue.

## Rejection gates

Reject and revise any set where two directions share any of these as their
primary treatment:

- page skeleton or section order;
- hero layout or headline composition;
- dominant image, crop, or image placement;
- navigation structure or CTA placement;
- typography pairing or type scale;
- component/card structure or surface system;
- interaction states or motion choreography.

Also reject a set when the variants differ only by colors, copy, font swaps,
corner geometry, shadows, or small spacing adjustments. Those are refinements
to one direction, not separate design directions.

A palette change, new headline, different border radius, alternate shadow, or
isolated font swap never satisfies a rejection gate by itself. The direction
must differ in structure and experience across several of the dimensions above.

## Compare before delivery

After building the directions, compare them side by side or in the same
rendered context. Verify that:

- each one is recognizable without relying on its palette;
- each one has a different hierarchy or composition, not just a new skin;
- each one has its own coherent copy, type, surface, component, and motion
  choices;
- all directions remain clear, usable, responsive, and faithful to the shared
  user goal.
- the comparison is based on the actual rendered pages, not only source code
  or design notes;
- every direction has completed its own enhancement pass.

If two directions converge, revise one before presenting the set. Do not
explain away similarity as consistency. Variety is intentional contrast within
a usable system, not random novelty.
